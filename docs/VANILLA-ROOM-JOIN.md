# 原版形式统一入房：改动与验收

日期：2026-10-09。分支：`codex/vanilla-room-join`，基于拉取 GitHub 文档更新后的 `3cd3a4d`。

## 行为

用户输入代码、公开列表描述符或地址，统一进入目标解析器和会话状态机。178 中继跳转再回到同一个解析器；不根据 Rukkit、RW-HPS、CNKD 等品牌选择入房实现。房间码必须由对应中继基础设施实际提供，统一语法不能发现不存在或没有映射的房间。

```bash
npx tsx src/cli.ts join rkc595
npx tsx src/cli.ts join list:0
npx tsx src/cli.ts join host.example:5123
```

176 是这里的网络/构建版本编号，不是让玩家寻找叫“v176”的游戏。实际测试直接使用用户平时玩的客户端建房。

## 修正内容

- 按 `byte + int + boolean + int count + Java UTF[]` 解析 178，选择原始源码使用的首个地址，再按通用连接语法解析。保留地址的端口和完整查询串，支持域名、代码、`get|` 和 `[TCP]`；不扫描二进制中的文本片段。
- 注册密码和每跳客户端身份使用原版固定 64 位大写 SHA-256。主服务器密码哈希迭代四次，每轮大写输出参与下一轮。MD5 保持小写。
- 151 参数初始值为 55、66，缺省参数沿用此前状态；type 6 追加有效第一参数。挑战的 14 位哈希保留前导零，type 2 使用原版 g() 乘法公式。
- 117 支持任意输入，113 支持重新输入密码。明确的房间号/密码提示使用已知值，其余请求由调用方回答，取消或超时结束连接。
- 主服务器并发请求完成协议头、失败状态、完整性和地址解析后再竞争，坏的快速响应不能抢占有效响应，结束后取消其他请求。
- 客户端报告自身 176 版本和默认校验和 678359601，不照抄中继的 0 或其他版本号。每跳重新派生身份并继续使用已配置代理。
- 超出跳转上限、坏包、过期异步输入和旧连接事件有明确处理；显式重新连接会重置跳转预算。CLI 在连接协商期间关闭输入也能退出。

`INTEGRITY_RWX_VARIANT`、`POW_REREGISTER`、`REDIRECT_DROP_QUERY` 的旧行为开关不再参与此流程。

## 调用方输入接口

```ts
session.on("inputRequest", (request) => {
  console.log(request.kind, request.prompt, request.target.label);
  // 收到用户回答后调用 request.respond(answer)；null 取消。
});
```

也可使用 `SessionOptions.onInputRequest` 返回 `string`、`null` 或对应 Promise；返回 `undefined` 时保留请求等待 `respond`。一个请求只回答一次，迟到应答不能写进新连接。默认输入超时 60 秒，可通过 `inputTimeoutMs` 设置。

单房 CLI 将下一行作为应答，`/quit` 退出。多房编程接口可以传 `onInputRequest`；多房 CLI 尚无按房间回答任意输入的命令。列表密码房在请求主服务器地址之前需要提供 `PASSWORD`，会话内输入接口不能替代这个前置步骤。

## 本地验证

最终回归：13 个测试文件、108 项测试通过，`npm run typecheck` 通过。包括原版固定哈希向量、前导零挑战、完整二进制跳转、两段 localhost TCP 握手、查询串含冒号、密码重试、输入取消/超时、旧异步事件隔离、主服务器竞争请求及 CLI 提前关闭输入。

`npm run test:coverage` 统计本次修改的会话、主服务器和协议模块，不代表整个仓库覆盖率。最终语句/行覆盖率 87.66%，函数覆盖率 86.41%，分支覆盖率 76.68%。

## 真实房间验证

| 目标 | 可核对证据 | 结果 |
|---|---|---|
| 公开列表的空 `SERVER` 房间，协议 176 | `get|` 解析到 `54.215.144.145:5134`；地图 `[p8]Many Islands (8p).tmx`；名册含 `rw-probe-A/B`；接收端收到 `协议自检 vanilla-check-mv0tikil` | 入房和双客户端聊天通过，两者退出 |
| 用户提供的 `rkc595` | 自动入口 `r.relay.corrodinggames.com:5123` → 下发 `c.relay.cnkd.fun:5123/kc595`；中继公告明确显示 `RKC595`；地图 `结盟🔴[z;p10]Crossing Large (10p)`；名册含房主 `Unnamed711` 和 `rw-vanilla-A/B` | 入房和双客户端聊天通过，两者退出 |

`rkc595` 的接收端实际收到：

```json
{"message":"原版协议自检 rkc595-check-mv0tzg9u","formatVersion":3,"senderName":"2号 rw-vanilla-A","senderConnectionId":4,"senderTeamId":1}
```

第一次聊天验收脚本精确匹配未带前缀的昵称，因服务器添加“2号”而超时；修正验收脚本后重新通过完整消息和发送者匹配，没有为此修改协议客户端。

`serverUuid` 是服务器身份字段，共享中继可能复用，不能单靠它证明进入了哪个房间。此处同时核对中继房号、地图、名册和接收端聊天。

## 边界与迁移

当前实现是 TCP / 176 聊天客户端，尚未实现原版可靠 UDP，也没有建立其他版本的一致协议配置。社区服务器若改变线路格式或要求额外认证，仍需依据实际证据处理；本轮两类真实目标通过不等于所有服务器都已验证。

本轮没有真实密码房测试；密码相关行为已有固定向量和本地会话测试。没有本轮长期在线、完整对局同步或房主操作的验收。

大写身份哈希与旧版小写字符串不同。即使保留 `data/client-uuid`，服务器也可能把升级后的客户端看成新身份。

完整静态证据和可读重建源码的三处错误见 [修复前审计](ROOM-JOIN-AUDIT.md)；字节结构见 [协议规格](PROTOCOL-SPEC.md)。
